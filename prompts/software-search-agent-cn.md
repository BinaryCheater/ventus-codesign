# Agent：实现软件变体及其软硬件优化抽象

读取 AGENTS.md、docs/project_tasks_cn.md、docs/baseline_cn.md 和 docs/instruction-programs.md。使用自己的独立结果目录，保留基线和旧数据，遵守私有执行配置。沿用统一面积、精度和线程配置。

目标：从 Qwen 的真实 GEMM 开始，实现“软件变体 → 可解释的参数抽象 → MIP 选择硬件与软件 → 指令模拟器复评”。不需要通用软件生成器，也不需要修改 LLVM。先做一个子图闭环，再接回整网。不要启动 512 全网运行。

按顺序完成：

1. 读取 model_program.py、mma_packed_bf16.cl、mma_reuse_bf16.cl 及编译资源记录。选取已有 Qwen 场景中一个真实 GEMM 形状，记录默认软件、完整 packing/计算/转换调用和基线周期。
2. 将输出 tile 16×16、16×64、32×64 暴露为明确的软件选择，检查形状、布局及尾块条件。保留原默认行为；现有 ELF 可以复用。若要降低不同变体的寄存器需求，写独立 OpenCL 变体并重新编译。同步修改 bundle 和调用组织，不能只修改模型里的工作量数字。可继续提出新变体，但先让这一轮可运行。
3. 检查输出索引、覆盖范围、packing 与转换，以及小尺寸和尾块的功能正确性。性能执行器不算完整张量值，不能代替数值检查；说明实际使用的检查方法和仍未验证的部分。
4. 为每个变体保存适用形状、tile、block 数、编译所得 VGPR/SGPR/LDS、指令工作量、读写字节、临时存储及依赖。区分有用字节与实际事务，cache miss 和 bank 冲突随硬件和访问顺序变化，不能视为固定流量。数据绑定源码、ELF 和配置 hash；公式注明来源。不得凭主观指定加速比。
5. 实现软件选择与硬件字段的 MIP 耦合，包含面积、合法性、驻留和主要执行/访存瓶颈。性能近似应说明假设；结构定义优先来自源码和编译信息。可分段或迭代补充近似，不预先穷举全部组合。保留求解状态、界和 gap。
6. 将解转为硬件 JSON、软件选项和实际程序描述；独立调用指令模拟器评估。同一 ELF 的硬件扫描无需重编译。比较预测与模拟周期，定位偏差后改抽象或程序，并保留前一轮证据。功能或资源不合法的变体修复后才能进入结果。
7. 输出简短结论：实际修改、可执行命令、软件选择与资源表、默认/仅软件/仅硬件/联合方案的子图周期和面积。子图结果不能写成整网收益。接入整网后再完成项目 A/B/C 和顺序优化对照。

调度约定：一个主 agent 顺序推进即可；工具进程由 agent 启动并检查完成状态。程序层面，由 Python 描述 kernel 顺序、缓冲和启动尺寸，当前 dispatch 串行执行。GPU 内部 block/warp 调度由模拟器处理，不把一次运行的发射顺序固定到所有硬件。线程宽度固定 32，每 block 一个 warp。

遇到缺失功能，先说明具体代码缺口并在本轮必要范围内实现。不要把尚未实现的自动控制器、软件接口或整网 MIP 写成现成功能。运行与修改相关的回归和仓库要求的检查；不跑 RTL 或重新综合来评估每个候选。
